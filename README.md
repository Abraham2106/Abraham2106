<details>
<summary><b>&nbsp;01 · ALAIRA</b> — <i>applied AI and governance across a product ecosystem</i></summary>

<br>

**2026–present.** At ALAIRA, I work on implementing AI within existing business processes. We define the task, connect the relevant information, test model behavior, and give people a way to inspect and correct the output. Applying governance frameworks early helps us run pilots with clear access boundaries, evidence, evaluation criteria, and human review.

- **ALAIRA Website** presents the product and shows how AI can prepare a case while keeping the final decision with a person.
- **ALAIRA Console** is a local workspace for projects, process baselines, cases, evidence, claims, versioned checks, evaluations, and human feedback. It includes an SLM playground for available local providers such as Ollama and QVAC, plus optional Qwen Model Studio access. Promptfoo evaluations can be imported, and traces can be sent through OpenTelemetry to a configured Langfuse instance.
- **Document Lab** tests document intake and review flows with synthetic data before they become part of a wider workflow.

My work includes model integration, retrieval and evidence flows, evaluation, and the application around them. Depending on the process, that can involve local models or on-premises, hybrid, and cloud setups. The console currently checks where evidence came from and how it is linked; people still judge whether it supports an answer and make the consequential decisions.

| :--- | :--- |
| **Stack** | TypeScript · React · Node.js · SQLite · Ollama · QVAC · Promptfoo · OpenTelemetry · Langfuse (optional) |
| **Deployment** | Local tooling today; local, on-premises, hybrid, and cloud options evaluated per process |
| **Governance** | Evidence provenance, access classification, versioned checks, evaluations, and human review |
| **Website** | [alaira-systems.vercel.app](https://alaira-systems.vercel.app/) |

<details>
<summary><b>&nbsp;02 · Oira</b> — <i>local AI for clinical documentation</i></summary>

<br>

**2026.** I built Oira around a simple tension in a medical consultation: taking notes can pull attention away from the person in front of you. It turns an ambulatory conversation into a structured draft that a clinician can review. I wanted transcription and inference to run on the device, keeping sensitive clinical data there.

The project brought together a desktop interface, a transcription pipeline, a local language model, and a review step. The output is a draft for a professional to inspect, not an autonomous clinical decision.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Electron · TypeScript · React · Whisper · Qwen3 |
| **Model execution** | Local transcription and inference |
| **Review** | Structured draft for a clinician to inspect |

</details>

<details>
<summary><b>&nbsp;03 · CaelusForge</b> — <i>governed apps from natural-language requirements</i></summary>

<br>

**2026.** I built CaelusForge to explore how natural-language requirements can become a useful internal application while keeping the generated result within clear constraints. It uses schemas and verifiable rules to shape what the application can do.

I used a constrained AST to limit what the generated code can express, then built the application around that contract with Next.js and Claude API. The interesting part for me is making generation easier to inspect, correct, and trust.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | Next.js · TypeScript · Claude API · closed AST |
| **Input** | Natural-language requirements and schemas |
| **Control** | Verifiable rules and constrained generation |

</details>
